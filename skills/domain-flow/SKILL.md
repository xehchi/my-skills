# domain-flow — חוקי הדומיין

> המקור: `docs/spec.md` §3, `docs/session-notes.md` §3. **קודם לכן — לבדוק בספציפיקציה.**

## 1. שלוש ישויות, שלוש מהויות

```
requests (פנייה)  — בקשה/מידע/משהו להנהלה. מגיש בשדה חופשי.
    │ "פתח תקלה" (כשהבדיקה העלתה תקלה)
incidents (תקלה)  — תופעה טכנית: מחשב/חדר/משאב.
    │ "הפוך למשימה"
tasks (משימה)     — עבודת צוות. יכולה להתקיים עצמאית או להיות מקושרת.
```
- **פנייה ≠ תקלה ≠ משימה.** אין לערבב. פנייה יכולה להיסגר `לא רלוונטי` / `הועבר להנהלה` בלי תקלה.
- **קישורים**: `incidents.request_id`, `tasks.incident_id`, `tasks.request_id`. **אחד-לכיוון** (ילד מצביע לאבא) כדי שלא ייווצר מעגל.

## 2. פניות — מעברים

| מ- | ל- | תנאי |
|---|---|---|
| — | `חדש` | יצירה (source, submitted_by, priority) |
| `חדש` | `בבדיקה` | נטילת הטיפול (`assigned_to`) |
| `חדש`/`בבדיקה` | `מטופל` | **אופציונלי** תקלה מקושרת. מותר "הסתפקתי בבדיקה" |
| `חדש`/`בבדיקה` | `לא רלוונטי` | לוג חובה: "מה בדיוק" |
| `חדש`/`בבדיקה` | `הועבר להנהלה` | סיבה חופשית |
- **העברה** `פנייה → פתח תקלה`: יוצרת incident עם `request_id`, `room_id/computer_id/resource_id` מה-פנייה, `description` מהפנייה (ניתן לערוך). סטטוס הפנייה — לא משתנה אוטומטית ל"מטופל" (הטיפול לא הסתיים). **אבל** ה-UI מציג תווית "הקימה תקלה #X".
- **סגירת תקלה** → הפנייה → **הצעה** לסמן `מטופל` (לא אוטומטי). אישור הצוות.

## 3. תקלות — מעברים + ירושה

| מ- | ל- | תנאי |
|---|---|---|
| — | `פתוח` | יצירה; חייב אחד מ: `computer_id` / `room_id` / `resource_id` |
| `פתוח` | `בטיפול` | `assigned_to` |
| `בטיפול` | `נפתר` | `resolution` **חובה** (מסמך המדיניות: תיעוד חובה) |
| `פתוח`/`בטיפול` | `לא נפתר` | `resolution` — למה לא |

**ירושת חדר — צפייה, לא שכפול:**
```js
// מסך מחשב: התקלות שלו + התקלות של החדר שלו (מסומנות "מהחדר")
function incidentsForComputer(computerId) {
  var c = computersRepo.get(computerId);
  var own = incidentsRepo.list({ computer_id: computerId });
  var room = incidentsRepo.list({ room_id: c.room_id, computer_id: null });
  return { own: own, fromRoom: room };
}
```
- תקלה עם `computer_id` — **לא** מוצגת באחי המחשב בחדר. רק במסך המחשב ובמסך החדר.
- מסך חדר — מציג את כל התקלות: שלו (`computer_id` null) ושל ילדיו (עם תווית "מחשב A14").
- **סגירת תקלה** → הצעה "להוסיף למאגר הידע?" עם טיוטת מאמר (כותרת = `description` קצרה; גוף = `resolution`).
- **"הפוך למשימה"** — הצעה כש`status`=`לא נפתר` או כשיש `resolution` עם "יקר/מורכב"; ידני תמיד.

## 4. משימות
- עצמאיות, או מקושרות (`incident_id` / `request_id`).
- `project_id` — לא חובה (ראו `project-mgmt` למושגים; הפרויקט שלנו קליל).
- סטטוס: `לביצוע` / `בביצוע` / `בוצע`. "היום"/"באיחור" — נגזרת של `due_date`.
- **תלות בין משימות** — מודל פשוט (`depends_on`): לא מאפשר `בוצע` לפני שהקודמת `בוצע`. ללא נתיב קריטי (לא נדרש לפרויקט הזה).

## 5. משאבים ותוכנות

**משאבים** — יצור פיזי; יכול להיות משויך לחדר או נייד. מעבר בין חדרים — `activity_log` מתעד.
**תוכנות** — קטלוג מרכזי, קישור רבים-לרבים:
```
software 1───* computer_software (computer_id, software_id, version, installed_at)
software 1───* room_software   (room_id, software_id, notes)
```
**דוח רישיונות (חשוב):**
```js
function softwareLicenseReport() {
  var sw = softwareRepo.list({ deleted_at: null });
  return sw.map(function (s) {
    var installs = computerSoftwareRepo.count({ software_id: s.id })
                 + roomSoftwareRepo.count({ software_id: s.id });  // "כל החדר"
    var over = s.license_type !== 'בלתי מוגבל' && s.license_count != null && installs > s.license_count;
    return { name: s.name, installs: installs, allowed: s.license_count, free: (s.license_count||0) - installs, over: over };
  });
}
```
- **התראה** (לא חסימה) כשעובר. `license_expires` קרוב (30 יום) — התראה נוספת.

## 6. שיבוץ — שתי שכבות (חודש עברי)

```
schedule_weekly   — תבנית: room + group + day_of_week + start/end + effective_from/to + active
schedule_monthly  — חריגים: room + group + date(Date ms) + start/end + kind(ביטול|הוספה|שינוי|חג) + note
```
- **תצוגה חודשית = generate(month)**: לכל תאריך בחודש — ה-column מה-weekly של אותו יום, ואז להחיל `schedule_monthly` של אותו תאריך:
  - `ביטול` → להסיר סשן
  - `הוספה` → להוסיף סשן
  - `שינוי` → להחליף שעות/קבוצה של סשן קיים
  - `חג` → להסיר את כל מה שבאותו יום (חופשה)
- **ימים:** ראשון–שישי. שישי — 8:30–19:30 ברירת מחדל.
- **התנגשות** — אותה חדר + **חפיפת שעות** → **אזהרה**, לא חסימה. שתי אפשרויות בצד ה-UI: "לשמור בכל זאת" / "לשנות". בכל מקרה — לסמן את ההתנגשות ולתעד.
- **חישוב התנגשות** — לפי חפיפה: `aStart < bEnd && bStart < aEnd`.

```js
function overlaps(a, b) {
  var as = hmToMin(a.start_time), ae = hmToMin(a.end_time);
  var bs = hmToMin(b.start_time), be = hmToMin(b.end_time);
  return a.room_id === b.room_id && a.day_of_week === b.day_of_week && as < be && bs < ae;
}
```
- **שתי קבוצות בחדר** — מותר, לאותו יום/שעה? **לא** (אותו חדר, אותה שעה). אבל שתי קבוצות שונות **בשעות שונות** — מותר.
- **הגרעין החודשי אינו נשמר** — נגזר בכל בקשה (Cache TTL 5 דק'). שמירה רק של החריגים.

## 7. הודעות ותזכורות

- **הודעות** — `recipient_id: null` = כלל-צוותי. "נקרא" אישי — גיליון/מפתח ב-`PropertiesService` כמערך של `{user, msgId, read_at}` (או sheet `message_reads`).
- **קישור דו-כיווני**: `messages.linked_entity = {type, id}` (JSON). במסך הישות — "הודעות מקושרות".
- **תזכורות** — יזומות ע"י משתמש, `remind_at` (ms), `user_id`. לא נוצרות אוטומטיות. `done_at` לסימון.
- **מחיקה קשיחה** להודעות — מותרת (`hard: true`), עם לוג.

## 8. דגלים אדומים
- "סגור פנייה אוטומטית כשהתקלה נסגרת" — **אסור** (האיפיון: רק הצעה).
- "שכפול תקלה חדרית לכל מחשב" — **אסור** (בלבול וכפילות). ירושה בקריאה בלבד.
- לשנות `start_time` ב-monthly כשיש תלות ב-weekly — הכלל: monthly **מחליף** את מה שה-generated. אם רוצים "רק להוסיף שעה" — `הוספה`.
- `kind='חג'` — להסיר את כל היום, **לא** להשאיר סשנים אחרים.
- דוח רישיונות בלי לספור התקנות בחדר — מפספס. חדר מכיל התקנה אחת *לכל מחשב*, אבל בדוח — לספור לפי "התקנה" (חדר = 1 אם הוא חושב כמקום? **החלטה**: במאמר מפורש, room_software נספר **כאחת** לכל חדר, לא לכל מחשב. לתעד את זה בפרויקט.)
- השוואת שעות כמחרוזות `"09:00" < "10:00"` — נכון במקרה זה, אבל **לא** `"9:00"`. תמיד `hmToMin`.
